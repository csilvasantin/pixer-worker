# Edición de textos de cápsulas / Capsule text editing

ES: En Stock, «Abrir en AINimation» recupera el guion guardado de las cápsulas con `externalRef=capsula-url:<hash>`. El editor muestra título, subtítulo, gancho, giro, remate, fuente, idea, tema y cifra. «Guardar borrador» guarda sólo en este navegador; «Recuperar original» descarta ese borrador. El vídeo es una referencia de la versión anterior, no una previsualización del texto nuevo. «Generar nueva versión y sincronizar» requiere la clave del Stock y encola el guion en el renderizador existente. La clave sólo viaja en una cabecera y no se guarda. La versión anterior se conserva; cuando se publica la nueva se oculta la anterior por orientación. Las dos orientaciones deben terminar para anunciar «publicada». La cola depende del renderizador de GrokBotBox; no se promete una hora de entrega. Los vídeos sin proyecto original siguen importándose al Cast y no ofrecen edición de su texto incrustado.

EN: In Stock, “Open in AINimation” loads the saved script for capsules with `externalRef=capsula-url:<hash>`. Edit the card title, subtitle, hook, twist, payoff, credit, idea, topic and figure. “Save draft” stores changes only in this browser; “Restore original” discards the draft. The video references the previous version and does not preview new text. “Render new version and sync” requires the Stock key and queues the script for the existing renderer. The key travels only in a request header and is never stored. Previous assets are retained and hidden per orientation when replacements publish. Both orientations must finish before status reports “published”. Rendering depends on GrokBotBox availability; no completion time is promised. Videos without a saved project still import into Cast without editing their embedded text.

## Contract

`GET https://api.admira.store/capsula/url/director?ref=capsula-url:<16 hex>` returns the exact `guion`, `cartelas`, `capsuleVersion`, opaque `revision` and current publication state. No prompt extraction or new AI synthesis is used.

`POST` to the same URL accepts `{revision, guion, cartelas}` with `Content-Type: application/json` and the existing Stock authorization (`X-Notify-Key` or internal ingest header). A matching revision and completed previous render are required. It archives the previous job, preserves source/media parameters, and conditionally updates the queue using the R2 ETag. Replies: `202` queued; `401` unauthorized; `409 revision-conflict`, `render-in-progress` or `version-limit`; `400` invalid script. No shared content changes while typing or saving a local draft.

MCP: this is an HTTP/browser workflow; no new MCP tool is claimed. Agents can inspect the contract and use the existing authenticated API. Do not put keys in URLs, prompts or repository files.
